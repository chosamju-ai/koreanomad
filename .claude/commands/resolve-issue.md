# resolve-issue

GitHub 이슈를 가져와서 해결하기 위한 상세한 실행 계획을 수립합니다.

## 사용법

```
/resolve-issue <이슈 번호>
```

## 설명

이 커맨드는 GitHub 이슈를 가져와 분석하고, 해결을 위한 구체적이고 실행 가능한 계획을 수립한 후 사용자의 승인을 받습니다.

## 지시사항

당신은 GitHub 이슈 분석 및 계획 수립 전문가입니다.

이슈 번호: **$ARGUMENT**

다음 단계를 수행하세요:

### 1. 환경 확인
먼저 필요한 도구와 환경을 확인합니다:

```bash
# GitHub CLI 설치 및 인증 확인
gh --version
gh auth status

# Git 리포지토리 확인
git rev-parse --git-dir
```

환경이 준비되지 않은 경우 사용자에게 안내합니다.

### 2. GitHub 이슈 가져오기
`gh` CLI를 사용하여 이슈 정보를 가져옵니다:

```bash
# 이슈 상세 정보 조회
gh issue view $ARGUMENT

# JSON 형식으로 가져오기 (파싱이 필요한 경우)
gh issue view $ARGUMENT --json title,body,labels,assignees,state,comments
```

### 3. 이슈 분석
가져온 이슈를 다음 관점에서 분석합니다:

#### 이슈 유형 파악
- **Bug**: 재현 방법, 예상 동작, 실제 동작 파악
- **Feature**: 요구사항, 기대 효과 파악
- **Enhancement**: 개선 대상, 개선 방향 파악
- **Documentation**: 문서화 범위 파악
- **Refactor**: 리팩토링 대상 코드 파악

#### 핵심 요구사항 추출
- 이슈의 목표가 무엇인지
- 어떤 문제를 해결하는지
- 성공 기준은 무엇인지

#### 제약사항 파악
- 기술적 제약사항
- 성능 요구사항
- 호환성 요구사항

### 4. 프로젝트 구조 파악
현재 프로젝트의 구조를 파악합니다:

```
src/
├── app/               # Next.js App Router
│   ├── layout.tsx
│   ├── page.tsx
│   └── cities/[slug]/ # 도시 상세 페이지
├── components/        # React 컴포넌트
│   ├── header.tsx
│   ├── footer.tsx
│   ├── hero-section.tsx
│   ├── city-card.tsx
│   ├── city-grid.tsx
│   ├── filter-bar.tsx
│   ├── bottom-cta.tsx
│   └── ui/           # shadcn/ui 기본 컴포넌트
│       ├── badge.tsx
│       ├── button.tsx
│       ├── card.tsx
│       ├── input.tsx
│       └── select.tsx
└── lib/
    ├── utils.ts
    └── cities.ts      # 도시 데이터 유틸리티
```

**기술 스택**: Next.js, TypeScript, Tailwind CSS, shadcn/ui

필요한 경우 코드 검색을 수행하여:
- 영향받을 파일 식별
- 관련 컴포넌트 파악
- 기존 패턴 확인

### 5. 영향 범위 분석
이슈 해결이 영향을 미치는 범위를 파악합니다:

- [ ] **컴포넌트**: 수정/추가해야 할 컴포넌트
- [ ] **라우팅**: 페이지/경로 변경 여부
- [ ] **스타일링**: CSS/Tailwind 변경 사항
- [ ] **타입 정의**: TypeScript 타입 추가/수정
- [ ] **데이터**: 상태 관리/API 변경
- [ ] **테스트**: 테스트 추가/수정
- [ ] **문서**: 문서 업데이트

### 7. 추가 정보 수집
계획을 수립하는 과정에서 다음이 필요할 수 있습니다:

- **코드 검색**: 관련 파일이나 함수 찾기
- **파일 읽기**: 기존 구현 패턴 파악
- **이슈 댓글 확인**: 추가 컨텍스트나 논의 사항 파악

필요한 경우 도구를 사용하여 정보를 수집합니다.

### 8. 사용자 승인 요청
계획을 수립한 후 반드시 다음 형식으로 사용자에게 승인을 요청합니다:

```markdown
---

## 📋 실행 계획 검토 요청

위 계획을 검토해 주세요. 계획이 적절하다면 승인해 주시면 작업을 시작하겠습니다.

### 질문 사항
1. [확인이 필요한 사항 1]
2. [확인이 필요한 사항 2]

### 다음 단계
- ✅ **승인 시**: Phase 1부터 순차적으로 작업 시작
- ✏️ **수정 필요 시**: 어떤 부분을 수정할지 알려주세요
- ❌ **거부 시**: 다른 접근 방법을 제안해 드리겠습니다

승인하시겠습니까?
```

### 9. 작업 시작 준비
사용자가 승인하면:

1. **TodoWrite 도구 사용**: 계획의 각 작업을 todo 항목으로 등록
2. **진행 상황 추적**: 각 작업 완료 시 todo 상태 업데이트
3. **이슈 업데이트**: GitHub 이슈에 진행 상황 댓글 추가 (선택사항)

### 10. 주의사항
- 이슈 번호($ARGUMENT)가 유효한지 확인
- 이슈를 가져올 수 없는 경우 사용자에게 알림
- 이슈 내용이 불명확한 경우 사용자에게 추가 정보 요청
- 계획이 너무 복잡한 경우 더 작은 단위로 분할 제안
- 반드시 사용자 승인 후에만 작업 시작

## 예시

```bash
/resolve-issue 123
/resolve-issue 45
/resolve-issue 7
```
