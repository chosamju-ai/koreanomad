# breakdown-task

작업을 세분화하여 구체적인 실행 계획을 수립합니다.

## 사용법

```
/breakdown-task <해결해야 할 문제 또는 기능>
```

## 설명

이 커맨드는 주어진 문제나 기능 요구사항을 분석하여 구체적이고 실행 가능한 작업 항목들로 세분화합니다.

## 지시사항

당신은 Next.js + TypeScript 프로젝트의 작업 분해 전문가입니다.

사용자가 제공한 문제 또는 기능: "$ARGUMENT"

다음 단계를 수행하세요:

### 1. 문제 분석
- $ARGUMENT를 분석하여 핵심 요구사항을 파악합니다
- 기능인지, 버그 수정인지, 개선 사항인지 분류합니다
- 비즈니스 목표와 기술적 목표를 구분합니다

### 2. 프로젝트 구조 파악
현재 프로젝트는 다음과 같이 구성되어 있습니다:

```
src/
├── app/               # Next.js App Router
│   ├── layout.tsx
│   └── page.tsx
├── components/        # 주요 컴포넌트
│   ├── header.tsx
│   ├── footer.tsx
│   ├── hero-section.tsx
│   ├── city-card.tsx
│   ├── city-grid.tsx
│   ├── filter-bar.tsx
│   ├── bottom-cta.tsx
│   └── ui/           # shadcn/ui 기본 컴포넌트
│       ├── badge.tsx
│       ├── button.tsx
│       ├── card.tsx
│       ├── input.tsx
│       └── select.tsx
└── lib/
    └── utils.ts
```

**기술 스택**: Next.js, TypeScript, Tailwind CSS, shadcn/ui

### 3. 영향 범위 분석
- 어떤 컴포넌트들이 영향을 받는지 식별합니다
- 새로운 컴포넌트가 필요한지 판단합니다
- 기존 컴포넌트 수정이 필요한지 확인합니다
- API나 데이터 구조 변경이 필요한지 검토합니다

### 4. 작업 세분화
다음 형식으로 작업을 세분화합니다:

```markdown
## 작업 분해: [문제/기능 제목]

### 개요
- **유형**: [기능 추가 / 버그 수정 / 개선 / 리팩토링]
- **우선순위**: [높음 / 중간 / 낮음]
- **예상 복잡도**: [낮음 / 중간 / 높음]

### 영향받는 영역
- [ ] 컴포넌트: [해당 컴포넌트 나열]
- [ ] 스타일링: [CSS/Tailwind 변경 여부]
- [ ] 타입 정의: [TypeScript 타입 추가/수정]
- [ ] 라우팅: [페이지/경로 변경]
- [ ] 데이터: [API/상태 관리]

### 세부 작업 항목

#### Phase 1: 준비 및 설계
1. [ ] [구체적 작업 1]
   - 파일: `경로/파일명`
   - 설명: [무엇을 왜 해야 하는지]

2. [ ] [구체적 작업 2]
   - 파일: `경로/파일명`
   - 설명: [무엇을 왜 해야 하는지]

#### Phase 2: 구현
3. [ ] [구체적 작업 3]
   - 파일: `경로/파일명`
   - 설명: [무엇을 왜 해야 하는지]

4. [ ] [구체적 작업 4]
   - 파일: `경로/파일명`
   - 설명: [무엇을 왜 해야 하는지]

#### Phase 3: 통합 및 테스트
5. [ ] [구체적 작업 5]
   - 파일: `경로/파일명`
   - 설명: [무엇을 왜 해야 하는지]

6. [ ] [구체적 작업 6]
   - 설명: 수동 테스트 및 검증

### 주의사항
- [고려해야 할 기술적 제약사항]
- [잠재적 위험 요소]
- [성능 영향]

### 다음 단계
작업을 시작하려면:
1. Phase 1부터 순차적으로 진행
2. 각 작업 완료 후 TodoWrite 도구로 진행상황 추적
3. 필요시 사용자에게 확인 요청
```

### 5. 추가 고려사항
- 각 작업은 독립적으로 실행 가능해야 합니다
- 작업 간 의존성을 명확히 표시합니다
- 파일 경로는 구체적으로 명시합니다
- 각 작업의 목적과 결과를 명확히 합니다

### 6. 출력
위 형식에 따라 작업 분해 계획을 출력하고, 사용자에게 진행 여부를 확인합니다.

## 예시

```bash
/breakdown-task 도시 목록에 즐겨찾기 기능 추가
/breakdown-task 헤더에 다크모드 토글 버튼 추가
/breakdown-task 도시 카드에 평점 표시 기능 추가
```
